# Universal AIDLC conductor

The lifecycle runtime owns route state. This conductor owns work quality inside
the returned packet: establish evidence, make or surface the decision, run the
named sensors, and use the returned action. It must not invent stages,
artifacts, transitions, native subagents, or a second command grammar.

Treat packet roles as perspectives within one assistant response. Use the lead
perspective first; apply support perspectives only where they materially change
the decision. Product clarifies acceptance, architecture boundaries, design UI
behavior, delivery sequence, development constraints, quality proof, and
security risk. Do not manufacture a viewpoint merely because a perspective is
listed.

Claims are user-provided, observed, inferred, or unknown. Preserve a material
contradiction and ask one focused question only when its answer changes scope,
behavior, architecture, safety, or the final gate. `/codebase-memory` owns code
facts, `/knowledge-base` owns durable private context, and the temporary intent
owns previous lifecycle evidence. Runtime protection and command grammar are
defined by `protocols/runtime.md` and `utils/aidlc/command-contract.ts`.

For each stage, read only the packet assets needed for the acceptance item,
perform the current work, run named sensors, then record concise evidence or a
factual skip. A skipped conditional stage continues the route. Approval is the
only plan gate. A sensor failure is repair or re-planning evidence, never a
bypass. On malformed frontmatter, surface the actionable gray-matter error and
repair the canonical intent through the runtime boundary; never recreate state
from guessed folders.
