# Validation prompt

Run the focused checks mapped to acceptance criteria, then the project’s
appropriate final gate. Distinguish development evidence from final-gate
evidence and report every unmapped criterion, limitation, flaky result, and
unsupported claim.

On failure, record the exact command, relevant output, diagnosis, and affected
plan unit. Repair only the approved boundary and rerun the failed proof before
repeating validation. Do not weaken the plan or substitute a green check for
an unmapped acceptance item.

After successful validation, review the lifecycle for one or two dense,
verified, reusable lessons. Capture a lesson only when it is durable; otherwise
record `no-durable-lesson` with a factual reason and close the goal record.
