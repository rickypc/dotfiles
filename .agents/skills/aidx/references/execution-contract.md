# AIDX execution contract

AIDX consumes the approved plan as its requirement boundary. It reads the
user-supplied path unchanged before canonicalization, validates the regular
file and six-section structure, and refuses traversal, symlink escape, wrong
index, malformed content, or missing proof.

The executor completes one workflow action and its fresh proof before beginning
the next. It uses only the plan's named owner and fallback. It does not
rediscover requirements, rewrite the plan, or interpret Markdown as a command
script. A material scope, ownership, safety, or acceptance change is a stop.

Before mutation, the executor builds a checklist from objective, requirements,
exclusions, dependencies, acceptance-to-proof mapping, and re-plan triggers.
For brownfield work it confirms current behavior, consumers, public or data
boundaries, preservation obligations, and existing proof. It keeps facts,
decisions, assumptions, and unknowns distinct. It re-plans when evidence
invalidates the approved requirement, boundary, owner, dependency, risk,
architecture, or validation strategy.

The smallest compatible implementation reuses verified extension points and
preserves relevant persistence, serialization, authorization, public types,
migration, rollback, external-boundary, UI-state, and NFR obligations. Each
acceptance item receives its own proof; focused checks do not replace the
configured final gate, and a green final gate does not prove an unmapped claim.

Completion requires fresh output and exit-status evidence, objective and
exclusion checks, changed-target review, and the exact Section 6 layout. A
previous receipt or partial green check cannot establish completion.
