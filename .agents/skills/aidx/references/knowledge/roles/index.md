# Engineering role reference map

Select only the discipline relevant to the current goal. The folders group
knowledge by engineering concern; they do not create separate AIDX states.

These branches are the method layer for the matching [AIDX role perspectives](../../roles/index.md).
Start with the perspective card to determine the required output, then load
only the knowledge files needed to make that output sound.

- [architect/index.md](architect/index.md) — architecture and non-functional
  design.
- [delivery/index.md](delivery/index.md) — planning and collaborative delivery.
- [design/index.md](design/index.md) — user experience and accessibility.
- [developer/index.md](developer/index.md) — implementation and data/API
  design.
- [product/index.md](product/index.md) — outcomes, requirements, and
  prioritization.
- [quality/index.md](quality/index.md) — testing, reliability, and validation.
- [security/index.md](security/index.md) — security requirements and threat
  analysis.
