# AIDX role perspectives

These role cards are review perspectives inside one AIDX response. They are
not separate agents, phases, approvals, or state transitions. Select only the
perspectives that can change the current goal decision.

Each card defines what that perspective must decide or produce. Follow its
matching [engineering knowledge branch](../knowledge/roles/index.md) only when
the goal needs the methods, patterns, or templates in that discipline.

- [architect.md](architect.md) — boundaries, interfaces, data, compatibility,
  dependencies, and implementation units.
- [delivery.md](delivery.md) — approval handoff, dependency order, risk, and
  proof for each increment.
- [design.md](design.md) — user flow, UI states, responsive behavior, and
  accessibility when a user interface is in scope.
- [developer.md](developer.md) — minimum implementation, owned tools, and
  evidence-backed code changes.
- [product.md](product.md) — outcome, acceptance, constraints, exclusions,
  assumptions, and material questions.
- [quality.md](quality.md) — acceptance-to-proof mapping, focused checks, and
  final-gate discipline.
- [security.md](security.md) — trust boundaries, secrets, permissions,
  dependencies, and proportionate controls.
