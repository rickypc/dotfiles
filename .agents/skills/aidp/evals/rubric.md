# AIDP Evaluation Rubric

The package also conforms to the shared six-part skill contract: role and scope, immutable operational rules, input and context schema, ordered execution chain, output and completion contract, and evaluation anchors.
The canonical matrix checks each heading and challenges brittle exact-output or robotic-persona language; the contract must remain compatible with this skill's uncertainty, ownership, and proof boundary.

Verify that AIDP owns clarification, template-driven and fail-closed plan
materialization, same-slug update routing, and atomic persistence while refusing
code execution or guessed requirements. Verify that every plan emits exactly
`ORDERED EXECUTION STEPS`, gives each item its own status checkbox, and inserts
an explicit `/skill-manager` item before any remaining skill-package change.
Verify that research examples are distilled into reusable patterns and that
project-specific domain content is explicitly discarded from reusable plans.
Verify that AIDP maps target responsibilities before decomposition, makes each
ordered item independently testable with exact proof and expected outcome,
rejects unresolved placeholders, and self-reviews objective/constraint/
exclusion coverage plus name/interface/dependency consistency before handing
off to AIDX.
Verify that AIDP performs README-first repository intake, checks present
primary files and high-signal directories, extracts documented commands,
separates explicit from inferred evidence, and records ambiguity. Verify that
refactor requests receive a behavior-preserving lane with coverage-gap review,
scope/exclusions, rejected alternatives, and smallest-safe-increment ordering.
Verify that language-aware plans identify the observed language/framework, read
the common and applicable profile guidance, select only relevant obligations,
and use the project-owned final gate rather than inventing a universal command.
